# macOS 原生命令取消验收

在已登录的 macOS 图形会话、仓库根目录运行：

```sh
python3 tools/check_native_jobs.py
```

工具编译并启动 `native_job_smoke`，使用真实 Wry 窗口、生产命令注册表和 `Webview::on_message`，以 camelCase JSON 请求经过 Tauri 参数解码、State/AppHandle 注入与响应序列化。Tauri test helper 只提供空 context/assets，不使用 MockRuntime。验收任务在后台线程运行，主线程继续处理窗口事件；`cargo test` 不启动这个 GUI example。

| 检查 | 预期结果 |
|---|---|
| 18 个长命令在任务槽忙碌时启动（含名称任务、播放及定位） | 拒绝请求，不发 `job:started`，原任务未被取消，批量 NFO 预览 token 未被消费 |
| 追加目标查找、视频查找、追加预览、元数据预览、NFO 预览、库健康检查 | 收到对应 `job:started` 后立即经 `job_cancel` 定向取消，任务槽释放，文件不变 |
| 批量 NFO 导出在启动事件处取消 | 返回取消结果，无完成项、文件修改或整理日志 |
| 不带 requestId 的来源自检 | 可正常返回；显式空来源列表不联网，不发归属事件 |
| 两项 NFO 导出在首项进度处取消 | 仅首项提交，返回一条结果、一个日志及取消标志；其索引已更新，第二项原字节不变 |
| 旧编号取消与撤销 | 旧 jobId 无法取消下一任务；经真实 rollback 命令恢复 NFO、sidecar 原字节和索引，视频字节不变 |
| 名称读取、预览、应用在启动事件处取消 | 三个请求各自确认归属；读取返回空取消结果，预览拒绝，应用无完成项，文件和日志数量不变 |
| 两部影片应用名称规则，首项提交后取消并撤销 | 仅首项制作商名称更新，NFO 的未修改节点保留，sidecar、日志及索引一致；第二项不变，撤销后原字节和索引恢复 |
| 播放、定位在启动事件处取消 | 校验前返回取消并释放槽；不带 requestId 的旧调用仍可得到正常查找错误，不发归属事件 |
| 登记软链接的播放、定位在读取字节后取消 | 两命令都在打开程序前返回取消；源视频、软链接 inode/目标、NFO、sidecar、日志字节及索引不变 |

库根为独立临时目录，只有中性合成影片和占位视频字节；媒体校验另在工具拥有的临时目录建立 1 MiB 源视频，经真实整理日志创建登记软链接。索引只通过 `Library::reindex_dir` 创建和更新。设置仅在内存中，不运行生产启动设置加载、日志初始化、网络请求、媒体服务器通知或系统废纸篓操作。维护预览/执行仅验证忙碌拒绝，未进入实际扫描或清理。工具不安装 opener 插件，回归导致意外进入打开路径时也只会失败，不调用播放器或 Finder。正常完成或断言失败时关闭临时库并清理目录；总超时 90 秒只终止本次探针进程并报错，强杀可能留下临时目录。

工具共十组检查。这里验证的是原生命令与磁盘链路。取消在原生 Rust 事件监听器内同步发起，确定发生在首项提交边界；未经过 WebKit 中的 JavaScript 事件投递，也不表示用户点击停止时一定只完成一项。媒体校验在非零字节进度事件处取消，小文件受生产限频影响可能已读到 EOF；不将此称为确定的中途读取。实际打开请求一旦交给系统就不能撤回，本工具不验证成功启动播放器。

共享前端模块和导入组件的实际事件投递由 [WebKit 桥接验收](native-bridge-check.md)覆盖；名称规则与媒体详情的时序回归见 `apps/desktop/tests/catalog-cancel.spec.ts`、`apps/desktop/tests/media-cancel.spec.ts`。完整原生名称/媒体详情组件操作、维护删除及真实媒体操作仍需分别验收。
