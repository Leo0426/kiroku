# 使用说明

从 README 移出的详细用法与边界说明。

## 使用(桌面客户端)

1. 首次启动选择**媒体库文件夹**(整理产物与索引所在,需要可写)。
2. 「导入整理」:添加待整理文件夹 → 扫描 → 刮削 → 预览计划(有冲突的默认跳过,可逐项取消勾选)→ 执行。
3. 「媒体库」:海报墙搜索/筛选,点开看详情,一键用系统播放器打开。
4. 「历史」:对有可读取操作日志的批次执行尽力撤销(文件移回原处,本批生成的 NFO 与图片删除)。原位置被占用时保留库内视频并报告冲突,处理后可重试。日志不是备份,新整理保护已有产物，新日志支持中断后的检查与尽力撤销；不能确认归属的文件保留并提示核对。

新增日常维护入口：

- 影片详情里的 **追加视频或字幕**：选择文件或文件夹，预览后确认；同号多目录需明确选择目标，无编号字幕需选择已有视频。idx/sub 成对追加，保留原有元数据、人工锁定和海报；同名同内容跳过并保留源文件，异内容冲突拒绝。追加可从结果或历史撤销。
- 普通导入发现已有影片时复用磁盘元数据，追加到原目录，不因命名模板改变而再建一部影片；仍需预览确认。
- **设置 → 数据源 → 来源自检**：使用已保存的路由、代理与 Cookie，区分可达、登录、拦截、限流、超时与异常响应，支持单站重测。可达不保证某个编号存在。
- **媒体库 → 检查媒体库**：只读报告缺视频、坏 NFO/sidecar、失效原图、缺图及索引差异；可打开目录、补缺图或启动索引重建，不自动改文件。
- **历史 / 设置 → 高级 → 安全空间维护**：保留期默认 90 天，只在明确预览、勾选与确认后清理无引用旧原图、已完整撤销且无依赖的旧历史/备份、非当日的旧文件日志。所有有效撤销、未完成记录和无法确认的引用保留；NFO 与 sidecar 引用也受保护。文件移到系统废纸篓，维护清理没有应用内撤销入口，需要时从废纸篓找回。容量为已识别文件的逻辑长度，硬链接不代表额外磁盘占用。

已有的媒体库(如 Jellyfin / Emby 目录)可在「设置 → 常规」里**从磁盘上的 NFO 重建索引**。

其他能力(都在「设置」里按分类开关):

- **数据源**:默认启用三个来源，另有多个默认禁用的可选来源；每个来源只支持部分内容类型，启用后需在设置中显式加入对应类型的路线，字段优先级可另行调整。各站域名、API 地址与 Cookie 可配置。直连会被 Cloudflare 挑战拦住的来源可经用户自行运行的 FlareSolverr 访问（[ADR-0007](adr/0007-external-challenge-solver.md)）。站点返回 403、526 等异常时只作诊断，不视为未命中。
- **整理**:命名模板(含可选组)、海报裁剪、剧照下载、字幕随迁;整理后把空出来的原文件夹移到废纸篓。
- **AI 翻译**:用 Claude 把外文标题、简介翻成中文(自备 Anthropic API Key)。
- **媒体服务器**:Plex 友好命名,整理/撤销后通知 Plex 局部刷新;Jellyfin/Emby 按路径通知刷新(可配路径前缀映射)。

恢复设计与限制见 [ADR-0002](adr/0002-durable-organize-journal.md):目标盘需支持硬链接安全发布,不支持时保留来源并报错;暂存链接不是独立备份。

新增 CLI 能力（追加与清理默认仅预览，加 `--apply` 才执行）：

```sh
cargo run -p kiroku-cli -- append ABC-123 /path/to/incoming --root /path/to/library
cargo run -p kiroku-cli -- sources-check <来源 ID>
cargo run -p kiroku-cli -- health /path/to/library
cargo run -p kiroku-cli -- maintenance /path/to/library --history-days 90 --log-days 90
```

追加字幕可用 `--video <库内视频路径>` 指定目标；同号多目录用 `--target <影片目录>`。保留期不使 Applied/Partial 历史自动失效，首版维护不会删除有效撤销依赖。

安全检查补充：已配置库的发现/读取失败会阻止整理，不按空库创建；已有根目录在预览后消失或身份改变时不重新创建。CLI 新建缺失库目录必须显式添加 `--create-library`；普通桌面选库仍通过原有创建入口。补图任务状态在健康报告与详情之间共享，取消按任务 ID 作用，切换页面不丢失当前补图结果。

命名变量、来源原文保存及逐片/批量 NFO 语言导出的用法见 [模板与语言说明](templates-language.md)。

五项扩展：

- 设置 → 名称规则：演员别名，以及标签、制作商、发行商、系列统一；选择已有影片后预览、应用、撤销，人工锁定优先。
- 新增两个备用来源，默认关闭，启用后须明确加入路线。
- 设置 → 常规：移动、复制、硬链接、软链接；后三者保留下载源并禁用源目录清理。链接需保持原位置可用；变更后可明确重新验证。模式、日志及边界见 [ADR-0005](adr/0005-source-preserving-placement.md)。
- 扩展命名变量与实际文件样例预览，限制 UTF-8 路径分量并保护编号/分片；更多用法见 [模板与语言说明](templates-language.md)。
- 保存来源原题/简介与本地化版本，详情或媒体库中明确预览导出 NFO 语言，支持撤销；不会自动重命名现有文件。Plex 仍依靠文件名与图片。

```sh
cargo run -p kiroku-cli -- catalog names preview /path/to/library /path/to/library/movie
cargo run -p kiroku-cli -- scrape /path/to/incoming --out /path/to/library --mode copy
cargo run -p kiroku-cli -- append ABC-123 /path/to/part --root /path/to/library --mode hardlink
cargo run -p kiroku-cli -- nfo-export /path/to/library/movie --root /path/to/library --language original
```

以上命令默认预览。名称规则明确使用 `catalog names apply` 执行，其它命令加 `--apply`；撤销使用产生的日志。Windows 继续最低优先级；实际跨卷、原生 GUI/播放器与媒体服务器兼容验收不以浏览器 mock 代替。

启动恢复入口：应用启动后只读检查中断/部分完成及损坏的整理日志，并在各页面顶部显示待处理事项。可查看日志位置或明确确认“检查并撤销”，不会自动修改文件。掉线时保留同一库的上次摘要，标为尚未核对，重新检查通过前禁止撤销；缓存只供显示。原生 UI 与真实外接盘验收仍需对应环境。
