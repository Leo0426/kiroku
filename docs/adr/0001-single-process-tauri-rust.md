# ADR-0001:单进程桌面应用 —— Tauri 2 + Rust 核心,不做服务化外壳

状态:已采纳(合并原 ADR-0001「Tauri 2 + Rust 核心」、ADR-0002「不做服务化外壳」与阶段 1 反爬 PoC 结论)

## 背景
- 目标是 macOS / Windows 的轻量桌面应用:包体与内存小,单进程,前端与核心进程内通信。
- 参考实现 amane 是「服务端 + 桌面壳」(多进程、HTTP 契约、监督协议),约 80% 复杂度来自服务化,而不是领域本身。

## 决策
1. GUI 用 Tauri 2(Svelte 前端),核心用 Rust(`kiroku-core`),CLI 与 GUI 共用同一套 `pipeline`。
2. 不做 HTTP API、WebSocket、监督进程、Docker、插件主机、播放反代;前端与核心走进程内 invoke / event,播放交给系统默认播放器。

## 依据:阶段 1 反爬 PoC(2026-10-06)
退出条件是「用 Rust 对两个主要数据源各连续请求 50 次,成功率 ≥ 95%,否则核心改用 Python(curl_cffi)+ PySide6」。

| 站点 | 结果 |
|---|---|
| 主数据源(同一搜索 × 50) | 1.5s 间隔:reqwest 74%、wreq(Chrome 指纹)60–86%,失败均为尾部连续 403;**5s 间隔两者都 100%**。瓶颈是按 IP 的频率限制,不是 TLS 指纹 → 同站点默认间隔定为 ≥ 5s,直连 reqwest 即可(wreq 保留在 CLI 的 `poc` 可选特性里备用) |
| 地区受限数据源 | 未判定:本机 IP 被重定向到 `not-available-in-your-region`,属于**地区封锁**而非指纹;需要对应地区出口代理后再验证(`KIROKU_PROXY=… kiroku poc <来源> 50 wreq`)。详情走其 GraphQL 接口 |

判定标准:状态 200 且正文含目标标记,不只看状态码。主数据源达标,Rust 核心保留;地区受限数据源的结论不影响本决策,只影响该数据源何时接入。

## 后果
- 爬虫用 Rust 重写;换来小包体(macOS 包约 21 MB)、双平台一套代码。
- 结构简单,但不支持远程访问与多用户;以后需要时另立 ADR。
