# ADR-0008：同编号多版本入库与替换

- 状态：接受（2026-10-15 已实现「并存」；「替换」暂缓）
- 日期：2026-10-15
- 关联：ADR-0002、ADR-0003、ADR-0005

## 问题与约束

常见场景是先下原版，后来又下到带字幕、4K 或其他版本。`append` 把同编号同分片映射到库里已有视频的路径，内容不同就报「目标已存在且内容不同」；库里已经有两个版本时，后续追加报「同分片有多个版本」。结果是新文件一直留在待整理目录。

约束：磁盘是唯一真相；不覆盖；所有文件操作都可回滚；清理只经过系统废纸篓。

## 决策

把「版本」定义为同编号、同分片、内容不同的视频。版本标签由 `code` 的相位推出（字幕 `-C`、`-U` 等版本标记、清晰度），推不出时用 `v2`、`v3`。

追加预览时，同分片已有不同内容的文件，用户为该项选一种处理方式，默认不选，保持现在的冲突状态：

1. **并存**：新文件命名为 `<已有视频主体名> - <标签>.<ext>`。这符合 Jellyfin 的多版本规则（同目录、同前缀、` - 标签`）。字幕跟随新版本主体名。元数据、海报和 sidecar 不变，只把新版本的相位并入角标，按 amane #200 的做法重新生成海报。
2. **替换**：新文件改用旧文件的路径。旧视频及其同名字幕先移到 `.kiroku/replaced-<journal id>/`，整批成功后再经 `TrashFn` 送进废纸篓。撤销时从暂存目录取回旧文件。

只有新增的 MoveFile/替换操作进入 v2/v4 日志，复用已有的意图、摘要和所有权证明。「替换」新增一种可撤销的 Op，需要扩展 journal 格式，并补 ADR-0002 的兼容说明。sidecar 增加 `versions` 列表（路径、标签、SHA-256），由 `reindex_dir` 读进索引，详情页列出各版本，「播放」默认播第一个。

## 不做

- 不按画质自动挑选或自动替换。
- 不跨编号合并，也不做模糊去重。
- 不改名已有的旧版本文件。

## 验证

- 单元：同分片三种情况（同字节 / 不同字节且有相位 / 不同字节且无相位）；多分片 × 多版本；字幕认领；分片名超过 240 字节时报错。
- 回滚：并存、替换在中途取消、失败、外部改动后撤销，都不丢文件。
- 实测：Jellyfin 是否合并为一部影片的多个版本；Plex 的行为另外记录。

## 代价

- journal 多一种操作，恢复代码更复杂。
- 「替换」短时间占用两份空间。
- 角标聚合后，重新生成海报会产生一次修订记录。

## 实现记录（2026-10-15）

已实现「并存」：
- `append` 发现同分片已有视频时，先比较摘要：与任一已有版本字节相同就按原逻辑跳过（字幕仍可随迁），否则以最短的已有视频主体名为前缀生成 `<主体名> - <标签>.<ext>`。标签依次取清晰度、字幕、其他版本标记；为空或被占用时用 v2、v3…。目标同时避开磁盘已有文件和本批其他目标。原先「同分片有多个版本」的冲突被这条规则取代。
- 摘要只算一次（`proofs` 缓存，执行前仍按原逻辑再校验）；只产生普通 MoveFile，沿用 v2/v4 日志与撤销，不改元数据、海报和 sidecar。
- `AppendPreview.new_versions`、`PlanItem.new_version`：导入计划把新版本项标为默认不勾选，带提示；桌面端显示「新版本 · 需手动勾选」，CLI `scrape` 需加 `--keep-versions` 才执行。详情页追加、CLI `append` 是用户明确选择的文件，预览即列出新版本目标。

暂缓：
- 「替换」需要一种新的可撤销操作（旧文件进暂存、整批成功后送废纸篓），要扩展日志格式并修订 ADR-0002，单独做。
- 角标按所有版本相位重新生成海报、sidecar `versions` 列表：当前追加保持「不改元数据和海报」的既有边界。
- Jellyfin 要求文件名以影片**文件夹名**为前缀；kiroku 以已有视频主体名为前缀，目录模板和文件模板不一致时 Jellyfin 可能识别为两部影片，待实测。
