# ADR-0012：按文件系统能力保留可核对的所有权证明

状态：已采纳（2026-11-17）。补充 ADR-0002 的发布方式与网络盘边界，其余先记录意图、不覆盖、摘要校验及显式恢复约束继续有效。

macOS SMB 与本机文件系统的硬链接、同步和属性查询语义不同：NAS 内部可创建的硬链接别名，不一定能通过 SMB 查询到。我们保留三种已有证明：本地暂存硬链接；不支持链接发布时的独占复制及已持久化目标身份；显式配置 SSH 映射时仅在 NAS 核验的恢复锚点。文件存在性、身份、摘要、恢复与锚清理集中在日志内部的所有权模块，持久化 Proof 格式不变。

复制发布必须先以 create_new 取得独占目标并持久记录其身份，再写入和校验；删源前仍核对身份与内容，部分发布无法确认时保留文件并报告。NAS 内部移动使用恢复硬链接及 renameat2(RENAME_NOREPLACE)，NAS 故障不自动降级为本机复制。配置缺失表示使用普通操作；配置存在但无效表示写入被阻止，不等同未配置。

没有选择“忽略不支持的同步/链接错误”或普通覆盖 rename：它们会丢失持久性或独占发布依据。代价是复制证明的额外空间与 I/O、NAS 的 SSH/Python/Linux 能力依赖，以及旧二进制对新复制证明的保守拒绝。可选 SSH 是短期调用，不部署常驻服务，不改变 ADR-0001 的单进程桌面形态。

显式能力检测只在新建临时目录验证当时的映射、硬链接、不覆盖移动、摘要和目录同步，不保证所有子目录或跨卷操作可用。当前验证包括 macOS 本地、已配置 NAS 上的 SMB Move/Copy 与 SSH 移动/恢复/撤销；不由此宣称 Windows、任意 NAS、断电或跨进程最终竞态已经验证。复验范围见 [NAS 文件操作](../nas-operations.md)。
