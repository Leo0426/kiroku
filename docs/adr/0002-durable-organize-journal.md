# ADR-0002：先记录意图，再安全发布与恢复

状态：已采纳（2026-10-07）。

## 决策

- 新整理保护全部已有产物：预览列出冲突，执行时独占发布，不提供覆盖开关。同号分片共享元数据的冲突影响整组。
- v2 日志在每个文件副作用前持久记录意图，以目标盘暂存文件、SHA-256 和同 inode 所有权证明决定恢复；跨盘复制并核对后才删来源。撤销进度持久化后才清理证明。日志不可写即停，不能确认归属时保留文件并报告；恢复由用户从历史显式发起。
- v3 元数据修订先准备独立旧内容备份，预览和保存均核对预期摘要；撤销只恢复可验证的新内容，外部修改保留冲突。旧 v1/v2 仍可读，多文件修订允许部分完成并由日志恢复，不承诺整体原子性。
- v3 修订活跃 v2 产物时，仅在根、路径、摘要和 inode 都匹配有效 proof 后记录 `before_owner`；逆序撤销从经复核的 v2 暂存锚恢复原 inode，再允许 v2 撤销。无锚旧日志沿用独立备份恢复，非 Unix 不声明此锚可用。
- 补图沿用 v2 无覆盖操作；裁剪、锁定与重刮沿用 v3。内容寻址原图在确认后保存，删除前重查真实 sidecar 引用；仍被引用或无法确认时保留。索引仅通过 `Library::reindex_dir` 更新。

## 代价与边界

目标盘须支持硬链接安全发布；暂存链接不是独立备份，内容原位变化由摘要检查阻止盲目撤销。目录清理只进系统废纸篓且不能触及媒体库及其祖先。根别名只在库根归一，库内 symlink 仍拒绝。实际异卷、网络盘、断电、Windows、ACL/xattr 和跨进程最终竞态不作已验证声明。
