# macOS WebKit 取消桥接验收

在已登录且屏幕解锁的 macOS 图形会话、已安装 `apps/desktop` 的 pnpm 依赖后，从仓库根目录运行：

```sh
python3 tools/check_native_bridge.py
```

Vite 使用现有 Svelte 插件，将测试入口、实际 `api.ts`、`events.ts`、`cancellable-job.ts`、`importflow.svelte.ts`、`state.svelte.ts`、导入组件和 Toast 构建到独立临时目录。`native_job_smoke --webview` 在真实 Wry/WebKit 窗口加载这些静态文件，使用生产 Context 的 CSP/权限和同一个命令注册表，经过 JavaScript `invoke`、Tauri 事件投递与响应。窗口使用非持久 WebKit 会话；不启动 dev server 或完整 App 壳。联网用例另启动仅供测试的本机 TCP 响应服务，不增加应用服务进程或生产 HTTP server。

工具启动前检查控制台解锁状态；运行期间请保持屏幕解锁、测试窗口可见。锁屏时 WebKit 的 `requestAnimationFrame` 可能不再回调，组件点击的帧等待设有五秒截止，失败会报告缺少渲染帧并进入清理。可设置 `KIROKU_BRIDGE_TRACE=1` 输出命令名定位卡点，不输出命令参数。

| 场景 | 断言 |
|---|---|
| 监听建立前立即停止 | 前端 helper 拒绝 promise，原生命令未启动 |
| 任务已取得槽、started 延迟投递 | 保留停止意图，忽略不同 requestId 的事件；收到正确事件后只取消对应 jobId |
| 忙碌拒绝、已完成 helper 再次停止 | 不取消当前其他任务，不发送无归属取消 |
| 真实 NFO 预览取消 | 前端通过实际 API 收到 started，再调用 helper.cancel；原生命令响应取消，不产生文件修改或日志 |
| 真实两项 NFO 导出 | 实际前端 API 调用生产预览/提交，返回两项成功结果；磁盘 NFO 标题和 sidecar 语言更新，扩展 XML 与视频保留，索引投影一致 |
| 实际撤销 | 经前端 API 逆序撤销，临时库的 NFO、sidecar、视频原字节及索引恢复 |
| ImportFlow 批刮削取消后重试 | 实际来源解析第一项成功、第二项本地响应尚未结束时，经 flow.cancel 定向停止；槽释放、第一项前后端结果保留、第三项不请求；再次刮削仅请求未完成两项，三项结果合并正确 |
| ImportFlow 详情页取消后重试 | 实际 scrape_url_start 在本地响应未结束时取消，不发布元数据；同一页随后重试成功，前后端标题与来源一致，任务槽释放 |
| 导入组件完整往返 | 挂载实际 Import.svelte 和全局样式，程序激活 DOM 控件完成扫描、刮削/停止、详情页表单、重试、预览、复制整理及撤销；检查步骤、按钮禁用、结果卡、三项文件/日志/索引及撤销恢复 |
| 重建事务中取消 | 磁盘修改一部影片并新增一部，首个目录索引后经真实 API 定向取消；原索引保留，磁盘与日志不变；真实完成先于启动响应到达 AppStore，确认归属后才渲染取消 Toast 和发起一次通知请求 |
| 重建重试及恢复 | 重试真实重建得到三部影片的新索引，再恢复临时磁盘并重建回两部；核对索引内容、文件字节、日志、任务槽和完成通知次数 |

前三项使用只存在于 example 的可控任务，以稳定重现“后端已开始但前端尚未知道 jobId”的时序。真实预览场景由测试控制命令暂时持有 `settings_writer`，让 JavaScript 有机会确认取消响应，再释放等待点；生产命令实现不加延迟或测试分支。导出、撤销和索引读取全部调用生产 API。工具在命令分发前记录 `job_cancel` 和 `notify_finish` 的参数，不替换或改写命令结果。

重建场景使用 `native_rebuild_bridge.rs` 中的 Rust 测试事件监听器，在真实 `library:progress` 首项完成时有界暂停事务。WebKit 收到等待事件后发送对应 jobId 的取消，再释放等待点；不向生产代码加入测试分支。测试入口暂缓向 AppStore 交付实际 `libraryRebuild` 的启动响应，保留原编号与实际事件，确定性覆盖完成先到的顺序。实际 AppStore 初始化读取隔离的内存设置；系统通知关闭，只验证实际 `notify_finish` 请求，不验证系统弹窗。全部索引写入经过真实重建；测试控制仅修改或恢复自己创建的临时媒体、NFO 和 sidecar，并核对既有日志字节与数量不变。

当前验证状态（2026-10-23）：解锁图形会话后，正式入口的十一组完整运行全部通过，包括原有九组和新增两组重建场景。此前锁屏诊断停在旧导入组件的渲染帧等待，已由解锁后的完整运行补齐验收。类型/组件检查、构建、example 编译及独立审查通过，原有十组原生命令验收也通过。

联网用例由 `native_network_fixture.rs` 准备另一组中性临时视频。两组状态机用例直接调用 core 扫描并注入会话和内存设置；组件用例只设置来源路径和内存设置，扫描会话为空，由实际“开始扫描”按钮调用 `scan_start`。只有一个来源启用，地址指向 `127.0.0.1` 临时端口，以最小中性 HTML 驱动生产来源解析器；AI、系统通知和媒体服务器关闭，子进程清除代理环境并为回环地址设置 no-proxy。ImportFlow 的启动、取消、重试和事件处理原样运行，不替换 API/事件结果。

组件用例的子进程 `XDG_CONFIG_HOME` 固定为本次静态产物临时目录下的 `.config`；Rust 准备控制先核对 `Settings::default_path()` 与预期临时路径相等，不符则拒绝进入扫描。扫描实际保存这份隔离设置，落盘断言核对来源、库根及复制模式。整理关闭原目录清理，所有源文件保留；撤销后新目录消失、新索引条目移除，既有库文件和索引保持原值。日志状态和三项条目数也从磁盘重读核对。

文件系统枚举不保证编号顺序；组件用例在真实扫描结束后按本次顺序设置第二个请求的测试服务等待点，不重排 UI 或后端扫描结果。DOM 控件按实际名称定位，滚动后触发 click/input，覆盖真实组件处理函数及渲染状态；不代表人工鼠标/键盘命中、文件选择器或完整应用导航验收。

服务先发送部分 chunked 正文，保持连接直到 JavaScript 已收到取消完成并验证状态后才释放；此处观察的是服务端部分响应尚未结束，不直接观测客户端内部读取阶段。实际请求路径、后端会话元数据、前端结果与取消 jobId 均有断言；每个临时输入退出时核对原字节，原媒体库也保持撤销后的字节和日志数。服务使用可停止监听、连接超时，显式停止并 join；macOS 接受连接后显式清除继承的非阻塞标记。

媒体库复用[原生命令工具](native-job-check.md)的中性临时 fixture。测试只保存上述隔离配置，不加载或保存用户设置，不访问外部站点、不通知媒体服务器、不访问真实媒体或废纸篓。静态产物、隔离配置、临时库和本机响应服务正常结束时清理；子进程超时 60 秒仅终止本次探针并报错，强杀可能留下临时目录。

本工具覆盖前端共享模块、导入组件、重建状态与 Toast、原生命令、本机 HTTP 和临时文件；不覆盖完整设置页面、其他完整页面、每个命令的取消、真实站点、代理/求解器、维护删除或人工点击时机。批量提交的逐项取消边界由原生命令工具另行验证，不能从这里推断“点击停止后只会再完成零项”。
