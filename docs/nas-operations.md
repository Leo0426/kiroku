# NAS 内部文件操作（可选）

桌面端和 CLI 启动时读取设置文件同目录的 `nas-operations.json`。未配置时保持原有本地文件操作。配置示例：

```json
{
  "host": "my-nas",
  "local_root": "/Volumes/Media",
  "remote_root": "/volume1/Media"
}
```

`host` 使用本机 SSH 别名或主机名，需提前配置免交互认证及可信主机密钥；NAS 需有 `python3`。本机挂载目录和服务器目录必须对应同一份文件。首次使用通过临时随机探针核验映射，挂载身份变化后重新验证。

映射范围内的视频由 NAS 创建日志恢复锚点，完成身份和内容校验后使用 Linux `renameat2(RENAME_NOREPLACE)` 原子移动；目标已存在时不会覆盖。锚点仅通过 NAS 检查，避免 macOS SMB 对硬链接别名的属性查询不一致。NFO、图片等附件采用 SMB 独占复制发布，保留原有日志和回滚校验。源、目标必须支持硬链接且处于同一文件系统；SSH 或链接失败会报错，不会悄悄退回经本机复制。8 MiB 及以上文件的 SHA-256 也在 NAS 上计算，仍需要磁盘读取时间。已有同名目标不会被覆盖；中断恢复和撤销保留原有日志约束。跨映射范围的操作仍使用原有实现。

此功能不部署服务或常驻进程。文件路径作为 JSON 经 SSH 标准输入传递；服务器拒绝越界和符号链接路径；按 Unicode 等价形式匹配 Mac 与 NAS 文件名，存在歧义时拒绝操作。macOS SMB 的目录缓存可能短暂显示旧名称；恢复判断使用 NAS 上的实际文件身份。普通挂载属性查询短暂未找到时最多重试 75 秒，取消仍及时响应。配置修改后重启应用生效。

## 只使用已有来源缓存继续整理

CLI 可用 `scrape <源目录> --out <库目录> --cached-only` 预览；确认清单后加 `--apply` 执行。该选项不请求缺失的来源信息，无可用缓存的编号会跳过。图片仍优先使用缓存，缺失时按原流程下载；翻译使用独立翻译缓存。普通桌面刮削和未加该选项的 CLI 行为不变。

中断操作可用 CLI `recover-pending <日志路径>` 恢复，它保留已完成的操作，不执行整批撤销。随后重新扫描源目录继续剩余文件。
