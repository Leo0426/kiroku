# NAS 内部文件操作（可选）

桌面端和 CLI 启动时读取设置文件同目录的 `nas-operations.json`。未配置时保持原有本地文件操作。配置示例：

```json
{
  "host": "my-nas",
  "local_root": "/Volumes/Media",
  "remote_root": "/volume1/Media"
}
```

`host` 使用本机 SSH 别名或主机名，需提前配置免交互认证及可信主机密钥；NAS 需有 `python3`。本机挂载目录和服务器目录必须对应同一份文件。首次使用通过临时随机探针核验映射，挂载身份变化后重新验证。

映射范围内的视频由 NAS 创建日志恢复锚点，完成身份和内容校验后使用 Linux `renameat2(RENAME_NOREPLACE)` 原子移动；目标已存在时不会覆盖。锚点仅通过 NAS 检查，避免 macOS SMB 对硬链接别名的属性查询不一致。NFO、图片等附件采用 SMB 独占复制发布，保留原有日志和回滚校验。源、目标必须支持硬链接且处于同一文件系统；SSH 或链接失败会报错，不会悄悄退回经本机复制。8 MiB 及以上文件的 SHA-256 也在 NAS 上计算，仍需要磁盘读取时间。已有同名目标不会被覆盖；中断恢复和撤销保留原有日志约束。跨映射范围的操作仍使用原有实现。

此功能不部署服务或常驻进程。文件路径作为 JSON 经 SSH 标准输入传递；服务器拒绝越界和符号链接路径；按 Unicode 等价形式匹配 Mac 与 NAS 文件名，存在歧义时拒绝操作。macOS SMB 的目录缓存可能短暂显示旧名称；恢复判断使用 NAS 上的实际文件身份。普通挂载属性查询短暂未找到时最多重试 75 秒，取消仍及时响应。配置修改后重启应用生效。

## 只使用已有来源缓存继续整理

CLI 可用 `scrape <源目录> --out <库目录> --cached-only` 预览；确认清单后加 `--apply` 执行。该选项不请求缺失的来源信息，无可用缓存的编号会跳过。图片仍优先使用缓存，缺失时按原流程下载；翻译使用独立翻译缓存。普通桌面刮削和未加该选项的 CLI 行为不变。

中断操作可用 CLI `recover-pending <日志路径>` 恢复，它保留已完成的操作，不执行整批撤销。随后重新扫描源目录继续剩余文件。


## 配置状态与显式检测

设置 → 整理、导入的来源/计划页展示 NAS 文件操作状态。未配置时使用普通操作；配置文件损坏、不可读或参数无效时显示错误并阻止媒体写入、修订、撤销和维护。修正配置后需重启，不会静默按未配置处理。浏览和检测入口仍可访问。

「检测 NAS 文件操作」占用单任务槽，在后台创建自有中性临时目录，核验连接/映射、恢复硬链接、不覆盖移动、内容摘要和目录同步，再清理探针。可定向停止，离开组件时请求停止；结果不是长期有效的文件系统保证。错误区分配置、SSH、映射、链接、移动、摘要与同步阶段；当前挂载身份变化后重新核验。停止或掉线可能使临时探针无法清理，错误会保留，不处理任何媒体文件。

## 在桌面保留成果后继续

启动恢复事项中，可信 v2/v4 新整理日志如果尚未开始撤销，可选择「保留成果后继续」。确认后重新核对 pending 操作，保留已提交文件与原日志，并通过唯一索引入口更新受影响目录。文件恢复错误与索引错误分别报告，可再次核对重试；Partial 不会伪改为 Applied。v1、v3 修订、已开始撤销及不可信日志不提供此入口。

成功后进入新的导入流程，使用已保存的来源作为候选；用户检查或重新选择来源，扫描剩余视频并确认新计划。不会从日志推导来源根授权或自动执行旧计划。默认勾选「只复用已有来源缓存」；缺少缓存的影片明确提示补刮，图片与翻译仍可能联网。原日志只包含已执行操作与 pending 意图，不能恢复尚未执行的整个计划；若视频已移走但配套资料尚未写入，保留磁盘成果，需结合库健康检查核对缺失资料。

恢复开始前可取消；已进入磁盘恢复时先完成该安全边界及索引收尾，停止只阻止后续进入新的导入流程。CLI `recover-pending <库>/.kiroku/journal-<id>.json` 使用同一保留与索引收尾路径。

来源查询结果显示复用、缺失、配置失效、损坏、不可读的来源缓存计数，以及仅缓存模式跳过的影片数；这些是来源条目数量，不等于影片数量。设置 → 生成数据显示来源/图片缓存的逻辑字节数，不额外解码图片。整理结果分别显示视频完成/失败、未选择或冲突跳过、图片失败和索引错误；CLI 非零退出码仍可表示冲突跳过，摘要会解释。

## 2026-11-17 验证范围

| 环境/路径 | 证据 | 未覆盖 |
|---|---|---|
| 本机日志与缓存 | Rust 回归覆盖提交、中断、重载、撤销、外部替换、无效配置、缓存损坏/失效 | 真实断电、ACL/xattr |
| macOS SMB | `nas_durable` 三项显式测试：Move/Copy、索引重开、重载与撤销 | 任意 NAS/挂载选项、真实跨卷 |
| NAS SSH | `nas_ssh` 显式测试：能力探针、Unicode、碰撞、阶段中断、恢复/撤销及错误映射 | Windows、其它远端系统 |
| 原生桌面 | WebKit 实际恢复组件 → 确认 → 重载磁盘日志 → 缓存查询剩余文件 → 计划/执行 → 逆序撤销；核对文件、日志、索引 | 安装包升级、人工鼠标操作 |

显式 NAS 回归仅在新建临时目录中运行；环境变量 `KIROKU_NAS_TEST_ROOT`、`KIROKU_NAS_REMOTE_ROOT`、`KIROKU_NAS_SSH_HOST` 必须指向对应的测试父目录和主机。运行 `cargo test -p kiroku-core --test nas_durable --test nas_ssh -- --ignored --test-threads=1`。原生复验见 [WebKit 桥接验收](native-bridge-check.md)。


独立进程重启复验：`python3 tools/check_native_resume_restart.py`。第一个隔离进程通过 core 准备三项中性来源缓存、首项完整提交和次项 pending 后退出；新原生进程从磁盘设置启动完整生产前端，实际点击恢复、确认、剩余两项扫描/缓存查询/计划/执行，以及两批逆序撤销，最后核对源字节、目标目录、索引和日志状态。两个进程共用自建临时目录，检查配置路径隔离，不访问真实媒体或外部来源。此验收发现并覆盖恢复操作与后台待整理扫描争用任务槽的问题：恢复期间暂停后台扫描派发并等当前读取实际结束，收尾后再恢复队列。

## 0.2.6：网络卷索引与恢复等待

macOS 网络卷改用本机 `<设置目录>/library-index/<库身份>/library.db`，首次打开通过 SQLite 一致快照迁移旧索引；旧库内索引保留且不再写入。不要在客户端仍运行时手工删除或替换数据库。迁移遇到正在使用的旧索引会明确失败，可在旧任务结束后重新打开；不会把失败当成空库。恢复先完成文件安全核对，再更新影片目录索引；图片子目录归并到所属影片。持续数据库冲突停止整批重试，界面显示阶段、目录进度及未更新数。取消后保留原日志，未完成的索引可通过重新核对继续。实现边界与取舍见 ADR-0013。
